# AgriCoop Marketplace — Developer Setup & Maintenance Guide

## 1. Prerequisites

- **Node.js** 20+ (project uses `tsx`, Vite 6, React 19)
- **pnpm** 9+ (`corepack enable` then `corepack prepare pnpm@latest --activate`, or `npm i -g pnpm`)
- **PostgreSQL** database (Supabase-hosted or local). The app uses schema `agricoop_app`.
- **Supabase project** for Auth and Storage (or a local Supabase stack).
- Optional: **Docker** for the disposable local test database (`scripts/db-test/`).

## 2. Install

```bash
pnpm install --frozen-lockfile
```

## 3. Environment variables

Copy `.env.example` to `.env.local` and fill in values. **Never commit real secrets.**

| Variable | Purpose |
|---|---|
| `NODE_ENV` | `development` locally, `production` when built. |
| `PORT` | Local server port (default `3000`). |
| `APP_URL` | Public origin used for email redirects; must be HTTPS in production. |
| `DATABASE_URL` | Runtime PostgreSQL connection (least-privilege app user). |
| `MIGRATION_DATABASE_URL` | Owner-level connection used only by migration tooling. |
| `SEED_DATABASE_URL` | Owner-level connection used only by seed scripts. |
| `TEST_DATABASE_URL` | Local disposable test DB for `db:test:*` scripts (localhost only). |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL (exposed to browser). |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon/publishable key (browser-safe). |
| `SUPABASE_SERVICE_ROLE_KEY` | Server-only admin key — never expose to client. |
| `SUPABASE_STORAGE_BUCKET` | Default product image bucket (`product-images`). |
| `AGRICOOP_SEED_TARGET=local` | Required before running seed scripts. |
| `SEED_*_EMAIL/PASSWORD` | Test account credentials for seed scripts. |
| `QA_*_EMAIL/PASSWORD` | Credentials for authenticated Playwright E2E. |
| `AGRICOOP_AUTH_DIAGNOSTICS`, `VITE_AUTH_DIAGNOSTICS` | Optional auth debug logging (keep `false` in prod). |
| `VITE_APP_ID`, `VITE_FRONTEND_FORGE_API_*`, `BUILT_IN_FORGE_API_*`, `JWT_SECRET`, `OAUTH_SERVER_URL` | Optional legacy Manus/Forge integrations; can be left unset. |

## 4. Database setup

1. Point `DATABASE_URL`/`MIGRATION_DATABASE_URL` at a **development** database.
2. Apply migrations in order:
   - `drizzle/0000…0011` — base schema generated by Drizzle.
   - `supabase/migrations/*.sql` — applied in filename order; the latest is `20261205000000_permanent_user_deletion.sql`.
3. Verify RLS/grants: `supabase/rls.sql` and the migration files create security-definer helpers (`agricoop_app.*`) used by server-side `SET LOCAL ROLE authenticated` queries.
4. Seed reference data if needed: `pnpm tsx scripts/seed-defaults.ts` (categories, cooperatives, payment options).

> The repo also ships `scripts/db-test/` — a Dockerized disposable Postgres used by unit/schema tests. Run `pnpm db:test:up`, `pnpm db:test:setup`, `pnpm db:test:down`.

## 5. Run locally

```bash
pnpm dev        # tsx watch server/_core/index.ts on :3000
```

The Express server serves the Vite-built client in production and proxies `/api/*` to tRPC + Supabase Storage proxy routes.

## 6. Verify & test

```bash
pnpm check                 # TypeScript typecheck (tsc --noEmit)
pnpm test                  # Vitest unit/integration suite
pnpm test:e2e              # Playwright E2E (needs running app + QA_* creds)
pnpm build                 # vite build + esbuild server bundle -> dist/
pnpm start                 # run production build locally
```

## 7. Deployment (Vercel)

- `vercel.json` defines the build; `api/index.ts` is the serverless entry.
- Build command runs `pnpm build`; output is `dist/` + `dist/vercel-api.js`.
- Set the same env vars in Vercel project settings (Production/Preview/Development scopes).
- Database migrations are applied manually via `MIGRATION_DATABASE_URL` — **never** run them from the app at runtime.
- Storage buckets must exist in Supabase: `product-images`, `profile-verification-documents`, `coop-admin-applications`, `payment-proofs`, `system-payment-qr` (private buckets are served through the authenticated storage proxy).
- **Pre-deploy checklist:** see `docs/AGRICOOP_FINAL_DEPLOYMENT_READINESS.md` — env var matrix, migration preflight, Supabase Auth/payment prerequisites, smoke tests, and rollback plan.

## 8. Maintenance tasks

- **New migration:** add `supabase/migrations/YYYYMMDDHHMMSS_name.sql`, apply to dev DB first, then production during a maintenance window.
- **Schema changes:** edit `drizzle/pg-schema.ts` (authoritative Drizzle schema) and `drizzle/schema.ts`, then `pnpm db:generate` to emit a Drizzle migration. Keep `supabase/migrations` and Drizzle in sync.
- **Adding a router:** extend `server/routers.ts` or `server/part2Routers.ts`, register in `server/_core/app.ts`; add authorization checks via `server/authz.ts` helpers.
- **Adding a page:** create `client/src/pages/X.tsx`, add route in `client/src/App.tsx`, add nav entries in `client/src/navigation/*`.
- **Seeds:** only run with `AGRICOOP_SEED_TARGET=local` and dev DB URLs.

## 9. Safety rules

- Development DB only — never point `DATABASE_URL` at production for local work.
- `MIGRATION_DATABASE_URL`/`SEED_DATABASE_URL` must be owner-level but still dev-only.
- `backups/` is a protected local directory — do not commit or delete it.
- Do not commit `.env.local`, `users-backup.json`, or any file containing credentials.
- Payment proofs and ID documents live in **private** Supabase buckets; access is enforced by `server/_core/storageProxyAuth.ts`.

## 10. Common issues

| Symptom | Likely cause |
|---|---|
| `ECONNREFUSED` on boot | `DATABASE_URL` wrong or DB asleep (Supabase free tier pauses). |
| tRPC 401/403 | Role check failed — verify `approvalStatus` and cooperative scoping in `authz.ts`. |
| Storage 403 on image | Bucket policy or `storageProxyAuth` scope — check migration `20261120140000_storage_proof_upload_policies.sql`. |
| Type errors after schema change | Run `pnpm check`; widen nullable user refs (`number | null`) as done for permanent deletion. |
| Playwright login fails | `QA_*` creds missing or account suspended; check `e2e/` specs for expected env names. |
